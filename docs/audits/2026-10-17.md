## High

**H1 — `sw.js` VERSION not bumped for the uncommitted round.** `sw.js:12` is still `emberdeep-v29` (set in d051f6b). The working tree changes ~18 `src/` files and adds `firstrun.js` and `coach.js`; with the SW's cache-first shell, an installed PWA (the late-game daily save lives there) keeps serving the old files, and the old `game/manifest.js`/`ui/manifest.js` without the new scripts. Fix: bump to `v30` in the same commit; make `tests/all.html` fail if `src/` differs from HEAD's content hash while VERSION equals HEAD's (SUMMARY recommendation 1 is still open).

**H2 — Tip pacing clock outlives the hero: new heroes can get no tip cards for a long time.** `src/ui/tips.js` `readyAt` (module level, `let readyAt = 0`) is only ever raised: `readyAt = Math.max(readyAt, S.time + GAP/ARRIVE)` (the `updater`, and the `scene:changed` handler). `S.time` is reset to 0 by `scenes.startNewGame` (`src/core/scenes.js:56`) and replaced by the save's value on load. Repro: continue the late-game hero (S.time in the tens of thousands), close a tip card or change scene (readyAt ≈ S.time + 20), return to title, start a new game: S.time = 0 < readyAt, so every non-`NOW` card (rarity, dash replacement, sockets, lore, …) waits until the new hero has played as long as the old one. The first-ten-minutes pacing then silently turns into "no cards at all" for exactly the case the user does regularly (new class on a device with a veteran). Same hole when loading a different/earlier save. Fix: reset on identity change: in `tips.js` on `scene:changed` with `e.scene === 'town'` and `S.time < readyAt - GAP - ARRIVE` (or simply store `readyAt` relative: `if (readyAt > (S.time||0) + GAP + 1) readyAt = (S.time||0) + ARRIVE`). Add a smoke check: set `readyAt` high via `_tipPace`, set `S.time = 0`, expect a queued card to show. `ui._tipPace(true)` exists for tests but the game never calls it.

## Medium

**M1 — New events not in the contract / DESIGN.** `fte:flasks` (game → ui, `src/game/firstrun.js:82`, `src/ui/coach.js:229`) and `story:opening` (ui → ui, `src/ui/story.js:119`, `coach.js:227`) are absent from `tests/contract.json` and DESIGN §13; also undocumented are `flags.fte` (shape `{v, floor, town, upgrade, kills, flasks, quiet}`), `flags.coachSeen`, `map.inputs.first`, `game.fte/beginOnboarding/faintEcho`, `ui._tipPace/_coachState/_coachRows/_questDirty`. The contract scan did not fail, so it only checks names it already knows. Fix: add the two events with payloads, list the flag shapes in DESIGN §11, and let the contract scan fail on an emitted event with a listener that is not in contract.json or the allow list (SUMMARY rec. 2).

**M2 — Onboarding is not in the gate.** `tests/firstrun.html` is outside `tests/all.html`; `ui-smoke.html` covers the UI side (+26 checks) but nothing in `all.html` generates depth 1 and 2 with `inputs.first` (smaller depth-1 map 36–40 × 34–38, 12 monsters) and asserts: stairs reachable, every spawn reachable, no stuck gate, corpse rebuild identical when `flags.fte.floor` flips to false afterwards (`captureInputs` stores `first`, so it should be, but is untested). Also uncovered: old-save immunity (a save without `flags.fte` generates byte-identical depth 1/2 to HEAD). Fix: a sweep of ~40 seeds × depths 1–2 with `{inputs:{first:true}}` in `tests/world.html`, plus one old-save fixture compare.

**M3 — Game and items code emit player-facing text outside `strings.js`/`story_data.js`.** `src/game/lockdown.js:70` (`'Wave ' + room.wave + ' / ' + room.waves`), `src/game/perks.js:322` (`'Mark earned (' + … + ')'`, also prints the raw id with underscores replaced), `src/items/reqs.js:99` (`'Your gear no longer fits your stats: N piece(s) returned to the bag'`). Fix: move to `strings.js` and have the UI localise on the event (`ui:toast` with a `key`), or at least route through `G.ui.S`.

**M4 — Per-frame cost on old phones is unmeasured for the R17 extras.** `src/engine/render.js`: `drawBloom` (up to 24 scaled additive `drawImage` calls at radius `l.r*9`, only when `fr.hi` = `V.R > 1 && !fr.low`), up to 48 lights (14 when low), lava lights, contact shadows for every prop with a width, per-entity `U.motion.step/blend`. They are gated on `fr.low`, but the gate depends on `lowFx()` adapting after frames are already slow. The SUMMARY's `?perf` device check is still not present. Fix: run the oldest iPhone once with the FPS overlay; if bloom drops it under 50 FPS, cap bloom at 8 sources and skip it when `lowFx()` has tripped even once in the session.

**M5 — Coach does repeated work every 0.2 s.** `src/ui/coach.js:36-40` `bagUpgrade()` calls `ui._verdict` for every bag item (60 slots) every scan whenever `upgrade` is un-seen and no foe is near, and again each tick while the Bag hint is open (`coach.js:193`); `guide()` (including a full `m.tiles` scan on depth 1, ≤ 2,300 tiles) runs at 5 Hz and again on every tracker redraw via `_coachRows`. Fine on desktop; on an old phone it competes with the 60 FPS budget. Fix: recompute `bagUpgrade` only on `inventory:changed`/`equipment:changed` and cache the stair index per map.

**M6 — Skipping the opening drops the only explicit statement of the goal.** `story.js` `opening()`: Skip on the first scene calls `end()` which never shows the Elder's "reach the third floor" lines. The tracker row (`flags.fte`, main_1 accepted) and the stair arrow carry it, but nothing says *why* or what the rift is. Fix: on Skip, show one toast with `TX.fte.goDown` or the Elder's single sentence ("Go down. Reach the third floor.") via `ui.toast`.

## Low

- **L1 — `diedAt` is module-level and never reset on a new game or load** (`src/game/firstrun.js:66`). Die, go to title, load another hero with `flags.fte` and level ≤ 6: its first town arrival tops up the flasks and shows the toast. Reset in `beginOnboarding` and on `scene:changed` to `menu`.
- **L2 — Gentle-floor damage softening only touches monsters present at `scene:changed`** (`firstrun.js:73-75`). Anything spawned later (summons, raised dead, wave spawns) hits at full strength. Depth 1–2 have no lockdown/events now, so it is only summoner packs.
- **L3 — Upgrade drop is consumed even when no upgrade rolls** (`firstrun.js:58-60`): `f.upgrade = true` is set before `classWeapon()` can return `null` (16 tries of a level-1 uncommon). Move the assignment after a successful roll.
- **L4 — Faint Echo applies for the whole life of an `fte` hero** (any corpse at depth ≤ 3, even at level 50). Intended as a lesson; as a loophole it is a safe corpse run on 1–3 for veterans who started on this build. Gate on `p.level <= FLASK_LEVEL + 4` or `!f.floor` plus level.
- **L5 — `dash` tip suppressed forever for `fte` heroes** (`tips.js` scan: `!S.flags.fte`); if the coach's dash hint never meets its condition (hp < 65 % with a foe within 3 and the dash ready) the dash is never explained. Show the card once `coachSeen` lacks `dash` after depth 3 or level 8.
- **L6 — Coach `skill` hint needs `was('attack')`**; if the first monster dies before the attack hint shows, the skill hint never appears.
- **L7 — Name plates** (`render.js` plate block): `plX/plY` are stale on the first frame and when the player entity is culled; plates re-sort by distance every frame, so two equidistant elites can swap places and flicker; a stack of more than ~14 passes can push a plate above the screen (clip at y < 0 is not applied); `nPlaced` is unused; `plates[]` keeps references to dead entities (until overwritten). Add a `y >= 2` clamp and hysteresis (`score` plus a small bias for the plate placed there last frame).
- **L8 — Dead data:** `OPENING_LONG` (`story_data.js`) has no consumer; keep it only if the rewrite session wants it (it is listed for that).
- **L9 — Hard-coded NPC name in a string** (`strings.js` `fte.flasks`: "Sister Maren fills your belt") duplicates `data_monsters.js:164`; use `{name}` with the healer's name.
- **L10 — `OPENING` text now says "reach the third floor and tell me what you see"**; main_1's own description says the same, fine, but `OPENING.arrival` lost the 'she is glad' beat the rewrite may have wanted back (flagged by the note).
- **L11 — `playlog.js`:** `persist()` re-serialises up to 100 floors on every death and every floor end (a few ms; fine) but `saveOpen()` runs on every `visibilitychange` to hidden while logging and can write a 50 KB+ string on iOS at the worst moment; the log is opt-in, so left as note. Death rows are not persisted until the floor ends (`onDied` calls `persist()` before `cur` is pushed), so a crash right after death loses that row.

## Checked and sound
- **Existing saves untouched:** `flags.fte` is created only by `meta.js` `startNewGame` wrapper; every reader (`game.fte()`, `quests.js`, `hud.js`, `story.js`, `tips.js`, `coach.js`, `dungeon.js firstLive()`) treats a missing/non-object `fte` as "off". `GEN_VERSION` unchanged; RNG consumption identical when `ctx.first/ramp` are false (checked dungeon.js size branch, populate.js `left/pMin/pMax/elites`, `addLockdowns`).
- **Corpse floors:** `captureInputs` stores `first`, `generateDungeon` honours `inputs.first` over live state, `usedInputs.first` goes back into `map.inputs`; flipping `floor` at depth 3 does not change a stored corpse floor.
- **Save plumbing:** `flags.fte` and `flags.coachSeen` are plain JSON, copied by the loader's flag merge; `coach.js` repairs a non-array `coachSeen`; a hand-edited non-object `fte` is ignored everywhere.
- **Event shapes used by coach/firstrun** (`npc:interact {role}`, `input:skill/potion/classaction`, `monster:killed {monster}`, `item:picked {item}`, `scene:changed {scene, depth, map}`, `skill:learned`) match `contract.json` and the emitters; the helper functions called across teams exist (`ui._verdict`, `items.classProfile/verdict/dropItemAt/potionPrice`, `engine.worldToScreen`, `game.getActionMode/getClassAction/getExplored`).
- **Inventory autoSort batching** (`items/inventory.js`): `sortBatch`/`sortPending` are balanced by `try/finally`; the sorted result equals the old one.
- **Service worker:** all-or-nothing code install, separate bounded asset cache, no stale `v25`-style cache survives activate; only the VERSION bump (H1) is missing.
- **Text:** all new onboarding strings are in `strings.js` (`fte`, `tipcards.trader*`) and `story_data.js`; the coach DOM uses text nodes (no HTML injection).
- **New-class checklist / art-sound formats:** onboarding code is class-agnostic (`classProfile`, `getClassAction`); nothing in this diff touches the art or sound loaders' formats beyond the already-reviewed any-frame-count animation loader.
- **Balance:** the only onboarding balance lever is ×0.75 monster damage on depths 1–2 until depth 3 is reached, no elites, a faint Echo; BALANCE.md targets (hits to kill from depth 3 on) are unaffected, and old saves skip it.
