## 2. Cross-team mismatches

Calls into other modules that do not exist: `G.items.canEquip` (`inventory.js:482`), `G.items.gamblePrice` (`npc.js:281`), `G.items.LOOK_FAMILIES` (`inventory.js:315,338`), `G.game.grantMark` (`milestones.js:112`). All are guarded, so they pass the contract test and fail silently (UI-7a is the one with a real effect).

Shape mismatches:
- `settings.lootFilterRules` / `settings.sellFilter` — see items.md IT-1/IT-3 (the UI side of the same defects).
- **`G.meta.STORY` keys with no consumer anywhere in `src/`**: `WORLD_BOSS_IDS`, `FALLEN_COMBINED`, `RETURN_LINES`, `CAMP_GROWTH`, `INN`, `CLASS_GOALS`. `STORY.CLASS_GOALS` is keyed by class with ids like `warrior_stagger`, `warrior_unbroken`, `warrior_crowd`… (8 goals/class) while `G.game.CLASS_GOALS` uses `w_charge_stun`, `w_cleave_three`… (7 goals/class, different goals), and `ui/r16.js` renders the game's names. The lead's rewritten goal names/flavour will never appear until the two tables are reconciled (suggest: story owns name/flavour keyed by the game's ids; game owns the rule).
- `STORY.MILESTONES` keys differ from `DEFS` ids for four counters (handled by `ALIAS`, `milestones.js:34`) — fine but fragile.
- Events: `room:wave` (listened, never emitted); `milestone:reached`, `settings:changed`, `town:warmed` are emitted with no listener (harmless); `closecall:ui` is emitted by `risk.js:87` for quests (fine).
- `ui._TIPS.inn` is patched in at `r16.js:106` after `tips.js` loaded — ordering dependency (manifest order matters).

## 3. Save safety

- Save content is plain JSON (`S.player`, `flags`, `quests`, `stash`, `surface`, `settings`). `JSON.stringify` of the live player: any cycle (an entity reference stored on the player) would make `meta.save` silently return false forever (UI-4b) — no guard, no test. Add a `try/catch` that logs the offending key once.
- No schema version beyond `v:1` and no migration functions (`meta.js:38-41` returns null for any other version → "no save"). A future `v:2` bump without a migrator would orphan every save (the `.unreadable` copy mitigates, but nothing reads it back).
- Loading resets transient state (`cooldowns`, `effects`, `dead`, `sealed`) — good. `flags.corpse` is validated; `flags.collection`, `crateBonus`, `loyalty`, `stats`, `milestones`, `classGoals`, `tipsSeen` are trusted as-is (all append-only; `flags.stats` grows by one key per stat name and per `kills_<rarity>`/`killsBody_<body>`/`deathsBy_<cause>` — bounded by vocabularies today, unbounded if `cause` becomes free text).
- Bounties persist `desc` (UI-9). `lootFilterPresets`, `sellFilter.presets` capped (5/6).

## 4. Performance on old iPhones

- HUD is well gated (per-frame writes only on change). Costs I would still fix: `bagUpgrades` runs `ui._verdict` for 60 cells every second (`hud.js:348-353`, `:448`) — event-driven on `inventory:changed`/`equipment:changed` instead; `refreshSkills` calls `getSkillInfo` ×4 every second (allocates the synergy arrays); `milestones.check` and `defs()` (UI-7c); `quests.sideLines()` concatenates two arrays on every kill/pickup/gold event (`quests.js:166`).
- `G.emit` copies the listener array on every emit (`core/events.js:22`); `fx:spawn`, `fx:text`, `sfx` fire dozens of times a second in fights. Iterate by index with a "dirty copy" flag instead.
- Panels re-render by `replaceChildren` of the whole panel at ≤ 10 Hz while dirty (`core.js:337-343`); the game is paused while a panel is open so this is acceptable; icons are data-URL backgrounds cached by the engine (`icons.js:139-181`, caps at 400 then clears **everything**; with the 400-key cap a crate of 300 distinct looks thrashes).
- `meta.save` is synchronous and runs on `ui.close` (`core.js:249`), every level-up, legendary pickup, 60 s, `visibilitychange`, volume-slider change, and every scene change (`core/scenes.js:48`) with a ring write. Cheap today (≈0.1 ms stringify, a few ms of localStorage) but multiplied by the 7 copies (UI-4c); defer the scene-change save one frame after the first render.
- `lzPack` fallback (iOS < 16.4, no `CompressionStream`) builds a JS array of every output byte; fine for ≤ 400 KB.

- Dead/legacy: `ui._lootHides`, `room:wave` handler, `canEquip`/`gamblePrice`/`LOOK_FAMILIES`/`grantMark` guarded calls, `meta._noSave` is never cleared (reload clears it), `ui._VERSION '0.19.0'` vs `sw.js` `emberdeep-v25` vs DESIGN `v16` — three version strings; show the SW cache version in the menu (already partly: `menus.js:165`).

- Harness gaps: `tests/ui.html` uses stubs; `ui-smoke.html` and `all.html` run the real game, but (1) the service worker is explicitly not registered, so UI-1/2/3 and the update flow are untested; (2) canvas is not inspected; (3) the contract test passes guarded calls to non-existent functions; (4) nothing round-trips an **old save** (only same-build save→reload); (5) `all.html` rewrites `emberdeep.save*` keys — run it in a private profile (README warns).
