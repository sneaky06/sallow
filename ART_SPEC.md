# Art list and specification

Every piece of art in the game is currently generated by code. Each file below **replaces** one generated piece;
anything you haven't drawn keeps its generated version, so you can replace art one file at a time and see it in game.

## How to add a file

1. Save the PNG under `assets/` with the exact folder and file name given below (all lower case).
2. Add its path to the list in `assets/assets.js`, e.g. `'sprites/warrior.png',`.
3. Reload the game. (A file listed in `assets.js` that does not exist just logs a harmless "404" line and the generated art is used.)

## Rules for every file

- **Format:** PNG, 32-bit RGBA, transparent background. No JPEG, no indexed-with-matte.
- **Scale:** draw and export at **1×** — one drawn pixel = one pixel in the file. The game scales it up (about 3× on a phone). Never upscale before exporting.
- **No anti-aliasing, no soft brushes, no blur, no gradients-by-tool.** Hard pixels only. Transparency is fully on or fully off (the only exception is glow on effects/portals).
- **Outline:** 1 px outline in a very dark colour (not pure black — e.g. `#0d0b10`) around characters, monsters, props and icons. No outline on floor tiles.
- **Light direction:** from the top-left. Highlights on upper-left edges, shadow on lower-right.
- **Do not draw ground shadows** under characters or props; the game draws them.
- **Tools:** Aseprite (paid, best), LibreSprite or Piskel (free). Set the canvas to the sizes below and turn on the grid.

### Look: grim and grimy, never muddy

- Keep the **ground dark and within a narrow brightness range**; keep **characters, loot and props clearly brighter or clearly darker** than the floor they stand on. If two neighbouring things have similar brightness, change one.
- Base colours are desaturated: cold stone grey, bruise purple, bog green, rust, bone, dried-blood maroon.
- Use saturated colour only as accents: fresh blood red, sickly green, ember orange, spectral blue. One or two accents per sprite. Glowing eyes are a good single accent on monsters.
- Grime is **detail inside a surface**, not noise: cracks, stains, drips, moss, rust streaks, soot, blood spatter, cobwebs. Aim for 3–5 shades per material.
- Loot rarity colours are the brightest things on screen; avoid these exact hues elsewhere:
  `#c8c8c8` common, `#5b8cff` magic, `#ffe45b` rare, `#b65bff` epic, `#ff8a2b` elite, `#3ddc6a` set, `#ff3b4e` mythic.

## 1. Floor and wall tiles — `assets/tiles/<theme>.png`

One sheet per area. Five sheets: `town.png`, `crypt.png`, `caves.png`, `inferno.png`, `abyss.png`.

- **Sheet size: 128 × 672 px** = 4 columns × 14 rows of **32 × 48 px cells**.
- Inside each cell the floor is an isometric diamond **32 px wide × 16 px tall, sitting at the bottom of the cell** (rows y = 32…47). Diamond corners: left (0, 40), top (16, 32), right (31, 40), bottom (16, 47). Use the classic 2:1 pixel line (2 px across, 1 px down).
- Flat tiles use only that bottom diamond; leave the 32 px above it transparent. **Anything drawn above the diamond on a flat tile is cut off** (so no tall grass tufts or bridge rails), except stairs up.
- Tall tiles (walls, doors) rise **24 px** above the diamond: a block with a diamond top face (y = 8…23), a left face and a right face (each 16 px wide, 24 px tall, right face darker). The engine cuts walls down automatically when they would hide the player, so keep the top face readable on its own.
- Columns are **4 variants** of the same tile (the game picks one per position so floors don't look repeated; for floors roughly 56% column 0, 12% column 1, 19% column 2, 12% column 3 — make column 0 the plainest). For water and lava the 4 columns are **animation frames** instead (looping slowly: water about 3 frames per second, lava about 2).

| Row | Tile | Notes |
|---|---|---|
| 0 | Floor | 4 variants: plain, cracked, stained, debris |
| 1 | Wall | tall; 4 variants |
| 2 | Door | tall open doorway frame the player walks through; floor visible inside. Column 0 = doorway in a wall running top-left to bottom-right (the game mirrors it for the other direction); column 1 = optional hand-drawn other direction; columns 2–3 unused |
| 3 | Stairs down | must read instantly as a way down (dark opening, steps descending). Column 0 only |
| 4 | Stairs up | steps rising toward the back-left; may use the whole 48 px cell height. Column 0 only |
| 5 | Shallow water | 4 animation frames; floor visible through it |
| 6 | Grass | town mostly; dead/yellowed |
| 7 | Path | town mostly; mud, ash, cobbles |
| 8 | Shallow lava | 4 animation frames; glowing cracks over dark crust |
| 9 | Bridge | planks or stone slab, drawn to sit over water/lava/pit |
| 10 | Rubble | walkable debris on floor |
| 11 | Deep water | 4 frames; dark, opaque, clearly not walkable |
| 12 | Deep lava | 4 frames; bright, churning, clearly not walkable |
| 13 | Chasm | bottomless pit: near-black with a faint rim of the floor edge |

Area moods: **town** — dying settlement, mud and ash, leaning timber; **crypt** — cold damp stone, grave dirt; **caves** — wet black rock, pale fungus, stagnant green water; **inferno** — scorched basalt, glowing cracks, chains; **abyss** — flesh-and-void, pale tendrils, eyes.

Rows a theme doesn't use (e.g. grass in the inferno) can be left fully transparent; the generated tile is used instead.

## 2. Characters and monsters — `assets/sprites/<name>.png`

- **Sheet size: 640 × 80 px** = 16 columns × 2 rows of **40 × 40 px cells**.
- **Feet anchor:** the point on the ground between the feet goes at **x = 20, y = 34** in each cell. Keep it identical in every frame or the character will jitter.
- **Keep a 1 px empty margin** inside every cell edge; the game draws a coloured rim around special monsters and it gets clipped otherwise.
- The last death frame (column 15) stays on the ground as the body; draw any blood pool into that frame.
- A normal human is about **22–26 px tall** (head top around y = 9…12). Small creatures (rats, bats, imps) 10–16 px; brutes up to 34 px tall and 30 px wide.
- **Row 0: facing front-right** (toward the bottom-right of the screen, you see the face). **Row 1: facing back-right** (toward the top-right, you see the back). The game mirrors both rows for the left-facing directions, so **do not draw left-facing frames**. This means a weapon swaps hands when mirrored; that's fine.
- **Large creatures (bosses, golem):** use a **1280 × 160 px** sheet with **80 × 80 px cells**, anchor at **x = 40, y = 68**. The game detects cell size from the sheet width (width ÷ 16).

| Columns | Animation | Frames | Notes |
|---|---|---|---|
| 0–1 | Idle | 2 | subtle breathing / twitch; loops slowly |
| 2–5 | Walk | 4 | contact, pass, contact, pass |
| 6–8 | Attack | 3 | wind-up, strike (weapon fully extended), recover |
| 9–11 | Cast | 3 | raise, release (arms/staff up), recover |
| 12 | Hit | 1 | recoil |
| 13–15 | Die | 3 | stagger, falling, on the ground (last frame stays on screen ~8 s) |

Draw the weapon into the sprite. If a sheet is listed, the game uses it exactly as drawn (no recolouring).

## 3. Props — `assets/props/<type>.png`

- **Cell size: 48 × 64 px.** The centre of the floor tile the prop stands on is at **x = 24, y = 56**; the tile's diamond spans x = 8…39, y = 48…63. A prop may overhang its tile upward and sideways.
- Animated props: frames side by side in one row (sheet width = 48 × frames). Props with 3 or more frames loop at 8 frames per second; props with 2 frames alternate slowly (about 2.5 per second).
- Nothing may rise more than 56 px above the tile centre (that is the top of the cell).

## 4. Item and skill icons — `assets/icons/<shape>.png`

- **Size: 16 × 16 px** each, one file per icon, object centred. On the ground they are drawn at 1× (16 px); in the backpack and skill bar at exactly 2× or 3×, so every pixel stays square.
- Shown in inventory slots, the skill bar and on the ground. The rarity colour comes from the slot border and label, so draw the item in its natural colours.

**Items (23):** `sword`, `axe`, `mace`, `dagger`, `bow`, `staff`, `wand`, `shield`, `helm`, `armor`, `gloves`, `boots`, `belt`, `ring`, `amulet`, `potion`, `scroll`, `gem`, `gold`, `key`, `rune`, `orb`, `tome`.

**Skills (16):** `slash`, `whirl`, `fire`, `ice`, `bolt`, `poison`, `heal`, `buff`, `arrow`, `multishot`, `trap`, `skull`, `summon`, `leap`, `aura`, `star`.

Extra potion colours (optional): `potion_hp.png` (red) and `potion_mp.png` (blue), same 16 × 16 size.

## 5. Projectiles — `assets/projectiles/<shape>.png`

- **Size: 16 × 16 px**, drawn **pointing right**, centred; the game rotates it. No outline needed; bright and saturated.
- Files (6): `arrow`, `bolt`, `orb`, `fireball`, `shard`, `spit`.

## 6. Portraits — `assets/portraits/<name>.png`

- **Size: 48 × 48 px**, head and shoulders, facing slightly right. Shown exactly as drawn with no frame added, so include any border or background you want. If you draw a character sheet but no portrait, the game crops one from the idle frame.
- Files (10): the four classes (`warrior`, `ranger`, `sorcerer`, `necromancer`) and six townsfolk (`npc_merchant`, `npc_blacksmith`, `npc_mystic`, `npc_healer`, `npc_elder`, `npc_stashkeeper`).
